Documentation

Reference for eka 0.5.9. Run eka --help or man eka for the same information in your terminal.

Quick start

$ eka # list the current directory $ eka -lh # long format, human-readable sizes $ eka -la # include hidden files, plus . and .. $ eka -lSr # smallest files first $ eka -lt # newest first $ eka -R src/ # recurse $ eka -d */ # the directories themselves $ eka -F # append / * @ | = indicators $ eka --color=always | less -R

With several paths, files are listed first, then each directory under its own path: heading, as ls does. On a terminal the output is in columns; when piped it is one entry per line.

Options

When options compete for the same setting, the last one wins, as in GNU ls (-S -t sorts by time, -t -S by size; -F -p appends only /). Repeating an option is allowed.

Sorting

  • In the C locale (LC_ALL=C) names sort bytewise.
  • In any other locale (LC_ALL, LC_COLLATE or LANG, in that order) names sort ignoring case and accents, with punctuation before digits before letters, as GNU ls does in a UTF-8 locale. macOS and glibc (Linux) each have their own model.
  • Ties in size and time fall back to the name.
  • Directories are not grouped first unless you pass --group-directories-first.
Tip. For scripts that need a stable, locale-independent order, run LC_ALL=C eka.

Safe output

File names are arbitrary bytes. A name like evil\x1b[2J or report‮txt.exe can clear the screen, change the window title or disguise a file type when printed raw. Eka follows GNU ls:

  • On a terminal the default quoting style is shell-escape: a name the shell would need quoted is wrapped in single quotes and unprintable characters appear as $'\033'-style escapes, so every name can be pasted back into a shell.
  • When piped or redirected names are written as they are, because the output is data for another program. Use -b, -Q, -q, --quoting-style or QUOTING_STYLE to escape them anyway.
  • A newline in a name is always shown as ? when names are printed as they are (-N, literal, shell).
  • Unprintable means control characters (C0, DEL, C1), bidirectional overrides and isolates, line and paragraph separators, and bytes that are not valid UTF-8.
  • Link targets, path: headings and error messages are quoted the same way.
  • -R cannot loop: a directory that is its own ancestor (possible with -L) is reported as not listing already-listed directory and skipped.
  • No unsafe code (#![forbid(unsafe_code)]). Unrepresentable timestamps print ?.

Color

Colors are used only when standard output is a terminal, unless --color says otherwise. With --color=auto, a non-empty NO_COLOR and TERM=dumb turn color off; --color=always ignores them.

If LS_COLORS is set, eka uses it (keys di ln ex or pi so bd cd fi and *.ext patterns) on top of the GNU defaults. Otherwise it uses its own palette:

Shell completions and man page

Homebrew installs the man page and completions for you. Otherwise, eka --completions SHELL prints the script for bash, zsh, fish, elvish or powershell.

$ # bash: add to ~/.bashrc $ source <(eka --completions bash) $ # zsh: put the script in a directory of $fpath, then run compinit $ eka --completions zsh > "${fpath[1]}/_eka" $ # fish $ eka --completions fish > ~/.config/fish/completions/eka.fish

From a source checkout, ./install-manpage.sh installs the man page.

Replacing ls

Try it first as an alias; nothing else on your system changes:

$ alias ls=eka # add to ~/.bashrc or ~/.zshrc $ alias ll='eka -lh'

Aliases apply only to interactive shells, so scripts keep using the system ls. Eka is not yet 1.0 and a few GNU options are missing (see below), so leave scripts alone until you have checked what they use.

Known differences from GNU ls

  • Not implemented yet: --author, -D, -Z.
  • Sort order: eka approximates GNU collation. It matches GNU ls on Latin-script names, ASCII punctuation, digits and accented Latin-1 letters. On Linux it follows glibc; in a 900-name random-symbol test, 3 pairs differing only in punctuation and accents or case sort differently. Other scripts and language rules (Spanish ch, German ß) sort by code point.
  • Newlines in names: with --quoting-style=literal or shell (and -N) eka prints ?. GNU coreutils 9.4 prints it raw; newer versions print ?.
  • Column fit: eka lets columns fill the width exactly (total <= width), like recent coreutils. Ubuntu's 9.4 needs total < width.
  • Quoting: shell styles always use single quotes ('it'\''s'); GNU uses double quotes for a name with an apostrophe. locale and clocale styles are not implemented. With --quoting-style=shell, a name whose only special character is a control character is quoted by eka and left bare by GNU.
  • Bidi overrides (such as U+202E) are always unprintable. GNU decides by locale.
  • Wide characters: column widths count code points, so CJK is not measured correctly.
  • total counts 1 KiB blocks, as GNU does; BSD/macOS ls counts 512-byte blocks.
  • Attribute markers: on macOS -l prints @ for extended attributes but not + for ACLs. On Linux it prints + (POSIX ACL) and . (SELinux). The column appears only when some file has a marker.
  • -U/-f: eka puts . and .. first rather than where readdir returns them.

Found another difference? Open an issue with the command and both outputs.

Platforms and requirements

  • macOS and Linux, x86-64 and ARM64. Windows is not supported.
  • Building from source needs Rust 1.88 or later (edition 2024).
  • Release archives carry a build-provenance attestation: gh attestation verify FILE --repo alexlm78/eka.
